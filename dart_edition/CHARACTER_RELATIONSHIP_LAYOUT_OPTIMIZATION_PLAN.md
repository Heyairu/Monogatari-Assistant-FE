# 角色關係圖：四條線與排列優化實作步驟

## 1. 目標與範圍

本計畫整理兩項改善：

1. 將外在／內在與雙向關係拆成最多四條線，保留合併功能。
2. 改善節點、連線與標籤壅擠，提供聚焦閱讀、穩定排列與手動調整。

本次不實作組織文氏圖。排列與繪製責任應分開，讓未來能加入組織背景區域。

第 1–5 階段已實作。現有角色關係資料、快照、XML 保存與 Undo／Redo 流程繼續作為資料來源；視覺合併不改寫原始關係。

## 3. 先確定呈現規則

### 3.1 四通道定義

每對不同角色最多顯示四條線：

| 通道 | 方向 | 類型 | 建議樣式 |
| --- | --- | --- | --- |
| 1 | A → B | 外在 | 實線與箭頭 |
| 2 | A → B | 內在 | 虛線與箭頭 |
| 3 | B → A | 外在 | 實線與箭頭 |
| 4 | B → A | 內在 | 虛線與箭頭 |

以穩定的角色 ID 決定 A、B 與通道順序，不能依目前選取角色或遍歷順序決定。顏色只作為輔助，類型仍能透過線型與文字辨識。

空白描述不建立通道。只有外在時畫外在線，只有內在時畫內在線；兩層都空白時不畫線，但既有資料仍保留，並可從角色關係清單編輯。

### 3.2 篩選與合併

- 類型篩選保留「外在／內在／全部」，將 Both 顯示名稱改成「全部」。
- 新增獨立開關「合併相同的雙向關係」，建議預設開啟。
- 合併以「同一角色對、同一類型、相反方向、相同描述」為條件。
- 描述使用現有正規化結果並去除前後空白後作精確比較，不推測文字語意是否相同。
- 外在與內在各自合併，不要求另一層也相同。
- 合併後以雙向箭頭呈現，保留兩筆原始關係的定位資訊。
- 未解析的目標不做雙向合併；自身關係使用獨立迴圈路由，不套用兩角色通道。

例如 A、B 外在都是「同事」，內在分別是「信任」與「嫉妒」：開啟合併時畫一條外在雙向線與兩條內在單向線；關閉時畫四條線。

### 3.3 三種閱讀狀態

| 狀態 | 節點與連線 | 關係文字 |
| --- | --- | --- |
| 全圖概覽 | 顯示所有可見角色，連線淡化 | 預設隱藏，懸停或選取時顯示 |
| 選取角色 | 突出該角色、一階鄰居與相關線，其餘淡化 | 優先顯示相關標籤；放不下的完整內容放入側欄 |
| 選取角色對／連線 | 突出該角色對的可見通道 | 展開該對角色的各方向與各類型描述 |

既有「只看鄰居」仍可作為隱藏其他角色的選項。若類型篩選隱藏某些通道，詳細面板標示目前篩選並提供切換「全部」的入口。

## 4. 階段一：拆開資料關係與繪製通道

### 步驟 1：建立未合併的方向關係資料

- [ ] mapper 先解析全部角色與原始方向關係，再處理呈現篩選。
- [ ] 保留來源角色、目標角色、原始目標文字、關係定位、外在與內在描述、解析狀態。
- [ ] 節點集合與基礎連接拓樸不因類型篩選改變，避免切換外在／內在時重新排列。

### 步驟 2：建立繪製通道模型

- [ ] 將每筆方向關係展開成非空的外在／內在通道。
- [ ] 每個通道具有類型、方向、描述、穩定呈現識別與原始資料引用。
- [ ] 將合併邏輯移到呈現轉換層，依類型分別比較相反方向。
- [ ] 合併通道保留正反兩筆引用，讓編輯與刪除明確知道操作對象。
- [ ] 重新映射後檢查選取是否有效；失效時清除選取，不能誤選另一筆關係。

目前關係使用索引定位。新增類型與合併設定後，不可只以畫面中的通道索引回寫；必須沿用來源關係定位並在更新前核對。

### 階段驗收

- [ ] 四筆非空通道可獨立呈現。
- [ ] 只外在相同、只內在相同、兩者都相同、都不同時，合併數量正確。
- [ ] 空白、未解析目標與自身關係均有定義明確的結果。
- [ ] 合併及篩選不改變角色資料、快照與保存內容。

## 5. 階段二：四通道路由與編輯互動

### 步驟 3：改為角色對的通道路由

- [ ] 先依角色對分組，再依固定通道順序分配曲線偏移。
- [ ] 即使部分通道被篩掉，其餘通道仍維持原來的順序與偏移位置。
- [ ] 端點依節點邊界與通道方向計算，箭頭不得被節點遮住。
- [ ] 合併時使用固定規則分配雙向通道位置，避免無關角色對的線條跳動。
- [ ] 保留節點障礙避讓，通道間距依縮放後的可辨識程度調整。
- [ ] 點擊判定使用實際繪製路徑，避免只能點到舊中心線。

### 步驟 4：標籤與詳細面板

- [ ] 每個標籤只顯示單一類型與方向的描述。
- [ ] 標籤避讓依閱讀狀態分配優先順序：選取通道、選取角色的關係、其他關係。
- [ ] 無法安全放置的標籤不強行疊放；完整描述保持可由懸停、選取或側欄取得。
- [ ] 單向通道編輯面板清楚顯示來源、目標與內外類型。
- [ ] 合併通道提供分別編輯兩個方向，或明確選擇同步更新兩方向。
- [ ] 刪除操作沿用既有確認流程，清楚區分刪除目前類型、整筆方向關係及兩個方向；不要因視覺合併自動擴大刪除範圍。
- [ ] 驗證 Undo／Redo 與快照編輯仍能正確還原。

### 階段驗收

- [ ] 四條線、箭頭與線型可辨識，各通道可選取。
- [ ] 合併開關可還原完整方向資訊。
- [ ] 編輯與刪除只影響使用者明確選定的資料範圍。

## 6. 階段三：降低全圖資訊密度

### 步驟 5：實作三種閱讀狀態

- [ ] 全圖概覽預設隱藏常駐關係描述。
- [ ] 選取角色後突出一階關係，降低其他元素不透明度。
- [ ] 選取連線後突出該角色對，詳細面板列出各方向與各類型。
- [ ] 提供角色對選取方式，例如在角色摘要的鄰居清單中選取另一角色。
- [ ] 點擊空白處或清除選取時回到概覽。
- [ ] 搜尋聚焦沿用既有行為，並與閱讀狀態一致。
- [ ] 窄螢幕沿用可收合詳細面板，避免內容擠壓畫布。

### 階段驗收

- [ ] 全圖不再常駐顯示全部關係文字。
- [ ] 任一描述均可透過聚焦操作閱讀與編輯。
- [ ] 聚焦與類型篩選不觸發節點重新排列。

## 7. 階段四：排列責任拆分與間距修正

### 步驟 6：抽出排列與幾何計算

- [x] 將節點排列從 view 抽出，輸入節點、基礎拓樸、節點實際尺寸、排列設定與釘選位置。
- [x] 排列輸出角色座標與內容邊界；畫布尺寸由輸出推導。
- [x] 連線路由接收座標與通道資料，標籤避讓接收路徑及障礙矩形。
- [x] 繪製與點擊判定共用同一份幾何結果。
- [x] 快取排列及幾何，避免在縮放、懸停與選取時重跑完整計算。

建議新增獨立的 layout／routing 檔案，實際命名依專案慣例決定。組織背景日後可使用同一份角色位置，不需混入關係通道模型。

### 步驟 7：修正現有角色定位排列

- [x] 保留現有主角／配角／反派排列作為「角色定位」模式。
- [x] 用實際節點矩形與安全間距估算容量，納入文字縮放後的尺寸。
- [x] 移除扇區不足時以較小 spread 壓縮成員的做法。
- [x] 容量不足時先擴大扇區或半徑；剩餘碰撞透過有限空位搜尋修正，必要時擴大畫布。
- [x] 對排列結果進行矩形碰撞檢查與有限次修正，包含不同圈層之間的碰撞。
- [x] 四通道路由需求納入角色間的保留空間。
- [x] 高連接度角色附近保留額外空間，取代只做少量位置偏移。
- [x] 未解析角色維持獨立區域，同樣遵守節點間距。

### 階段驗收

- [x] 同組織大量角色不再因扇區壓縮而重疊。
- [x] 不同圈層與未解析區域的節點矩形不互相重疊。
- [x] 節點增加時畫布能擴張，完整內容仍可平移與適合畫布。

## 8. 階段五：關係群集與穩定位置

### 步驟 8：新增關係群集排列

- [x] 提供「角色定位／關係群集」排列選項。
- [x] 以角色對的基礎連接建立群集，不將四條呈現通道計算成四倍連接權重。
- [x] 群集內讓有關係的角色靠近，群集間保留空隙。
- [x] 孤立角色與未解析目標有獨立的安排規則。
- [x] 主角、配角與反派使用節點標記或樣式保留辨識。
- [x] 排列採穩定排序／固定初始條件與有限計算次數，同一輸入產生可重現結果。
- [x] 計算結束後再做節點碰撞修正，無法容納時擴大畫布。

### 步驟 9：位置快取、拖曳與釘選

- [x] 依專案與排列模式保存目前位置；切換專案清除舊狀態。
- [x] 類型篩選、合併、懸停、選取與鄰居檢視沿用既有角色位置。
- [x] 新增角色優先在鄰近空位放置，刪除角色不立即重排全圖。
- [x] 支援拖曳節點並與畫布平移手勢區分；座標需轉換到畫布空間。
- [x] 支援釘選與解除釘選，重新排列時保留釘選角色。
- [x] 未釘選節點避讓釘選節點；兩個釘選節點若被使用者放到重疊位置，保留操作結果並提示可調整。
- [x] 重新排列保留有效選取與縮放，必要時只修正平移以保持內容可見。

第一版位置狀態建議只保留於目前工作階段。跨重新開啟保存位置可另行設計，不在本計畫直接修改 XML schema。

### 階段驗收

- [x] 兩種排列模式均可使用，群集模式有明確角色類型標記。
- [x] 切換外在／內在／全部、合併及聚焦時，節點座標不變。
- [x] 拖曳後點擊路徑、標籤與箭頭同步更新。
- [x] 重新排列不移動釘選節點，不殘留其他專案的位置。

## 9. 測試與視覺驗收

### 自動化測試

- [ ] mapper：四通道、空白內容、各層獨立合併、未解析目標、自身關係。
- [ ] 原始資料引用：篩選與合併後編輯、刪除仍定位正確。
- [ ] 排列：穩定輸出、節點矩形間距、扇區超量、多群集、孤立角色、釘選避讓。
- [ ] 狀態：切換顯示設定不重排、選取失效處理、專案切換清除。
- [ ] widget：工具列、三種閱讀狀態、合併線的編輯範圍、窄螢幕操作。
- [ ] 既有回歸：關係編輯、Undo／Redo、快照、XML 往返保存。

優先擴充既有兩份角色關係測試，排列與路由的純計算可新增獨立測試。執行相關 Flutter 測試與變更檔案的靜態分析。

### 視覺場景

| 場景 | 驗收重點 |
| --- | --- |
| 兩人、四個不同描述 | 通道、箭頭與標籤辨識 |
| 外在相同、內在不同 | 三條合併結果與編輯範圍 |
| 單一角色連到大量角色 | 中心附近通道密度與聚焦閱讀 |
| 同組織、同圈層大量角色 | 扇區容量與擴圈策略 |
| 多群集且存在跨群關係 | 群集間距與跨群路由 |
| 長名稱、長描述與放大文字 | 實際尺寸、截斷與完整閱讀入口 |
| 小螢幕與不同縮放 | 面板、平移、點擊與拖曳 |
| 空資料、單角色、自身關係、未解析目標 | 邊界情況與資料可達性 |

四條線只能改善關係語意辨識，不能保證密集圖沒有交叉。驗收以節點不被自動排列重疊、聚焦後資訊可讀、每筆資料可操作為準。

## 10. 建議交付順序

1. 四通道資料與分層合併規則。
2. 通道路由、線型與編輯互動。
3. 三種閱讀狀態與標籤顯示策略。
4. 排列責任拆分與既有圈層間距修正。
5. 關係群集、穩定位置、拖曳與釘選。

每階段完成對應驗收後再推進下一階段。前三階段形成第一個可交付版本；第四、五階段完成排列優化。

## 11. 步驟 6–9 實作紀錄

本文件共有五個階段，步驟 6–9 對應階段四、五。排列、路由及資料修改已拆為獨立模組；選取與懸停只重算標籤避讓，沿用已快取的曲線幾何。繪製與點擊判定使用相同路徑。

角色定位以節點矩形對角線及安全間距估算圓周弦距容量，再做有限碰撞修正。關係群集使用去重的角色對拓樸；孤立角色使用緊湊列式排列，未解析目標位於獨立區域。穩定排序包含角色 ID 作為同名排序依據。

位置依排列模式保留於目前專案工作階段，支援拖曳、釘選、保留釘選的重新排列與專案切換清除。位置不跨程式重新開啟保存。未加入組織文氏圖，後續可沿用排列輸出的座標。
