# 修訂追蹤視圖規劃

## 目標與位置

採用 Word 的修訂窗格與定位方式，正文差異使用 Git 的逐行 `+ / -`，SideBar 資料使用物件及欄位級 `+ / - / *(Modify)`。

桌面排列：`導覽列 | SideBar 內容 | 修訂窗格 | 正文`。此處的 SideBar 指角色設定、章節選擇、世界設定等內容區；修訂窗格不放在最左側 NavigationRail 與 SideBar 內容之間。

現有入口為 `lib/main.dart` 的桌面 LayoutBuilder：在 `_buildPageContent()` 與 `_buildEditor()` 之間插入可收合窗格，兩側使用 `MonogatariResizeDivider`。窗格預設 320px，可拖曳至 280–480px；未開啟時不佔寬度。工具列提供「修訂」切換鈕，收合後保留變更數提示。

寬度預算必須重新分配：目前 SideBar 最小寬度為 400px，新增窗格後不能繼續僅以原有比例分配。先保留正文可用寬度（建議至少 480px）；容納不足時，修訂改為位於正文左緣的覆蓋窗格，提供關閉鈕；手機使用抽屜。視窗縮放不影響差異結果。

## 比較基準與模式

- 預設比較「開始本次追蹤時的固定快照 → 目前工作內容」，開始追蹤後保留基準；一般儲存、自動儲存不會清除修訂。
- 可選擇已有且可取得完整內容的歷史版本作為基準；只有 revision metadata 時，顯示「內容尚未取得」，不能當成無差異。
- 工具列清楚顯示基準名稱、版本、時間與比較目標。切換基準會重新計算，基準與目前內容均需鎖定版本以免結果混雜。
- 「比較版本」是唯讀檢視；「追蹤修訂」才提供接受／拒絕。兩者共用差異呈現，但不共用寫入行為。
- MVP 是兩個狀態的淨差異；同一段反覆編輯後改回原值便不顯示。不宣稱保存每次按鍵、作者或操作時間；精確作者歷程需要後續操作紀錄支援。

## 修訂窗格

```text
修訂                  [收合]
基準：開始追蹤 09/28 14:00
目標：目前內容
[全部] [正文] [設定]
範圍：目前章節 ▾   [上一筆] [下一筆]
正文 +3 / -2 行 · 設定 +1 / -1 / M2

▾ 正文／第一章
  第 12 行 → 第 12–13 行   +2 / -1
  - 她走進房間。
  + 她推開門。
  + 房間裡沒有任何人。
  [接受] [拒絕]

▾ 角色設定／林澪         *
  年齡                 *
  17 - > 18
  [接受] [拒絕]

▾ 世界設定／北境         +
  新增項目，可展開欄位
```

窗格按「資料類型 → 章節／物件 → 差異區塊／欄位」分組。預設只顯示有變動的項目；支援目前章節／目前 SideBar 項目／全專案範圍，並記住使用者選擇。

點選正文差異會切換章節、捲動至位置並暫時凸顯；點選設定差異會切換 SideBar 頁面、展開物件並定位欄位。已刪除內容以基準快照顯示，不重建原物件；刪除行定位至新版本相鄰的插入位置。

清單跟隨明確的選取與定位；捲動正文不強制捲動窗格，避免清單跳動。相鄰正文差異合併為區塊，提供少量上下文，長內容可展開。關閉篩選造成目前項目不可見時，清除選取並給出狀態提示。

## 正文：逐行 Git 差異

1. 以章節 UUID 配對，再比較 `chapterContent`。每個 `\n` 分隔一個邏輯行；自動折行不算新行。CRLF/LF 在比較層統一，原始儲存內容不因此被重寫。
2. 使用逐行 Myers diff 或等價演算法。保留空白及空行差異，不默默 trim；行末換行差異獨立處理，避免虛構額外正文行。
3. 新增行顯示綠色 `+`；刪除行顯示紅色 `-` 與刪除線。改寫一行呈現舊行 `-`、新行 `+`，統計為 `+1 / -1`，正文不另創 Modify 類型。
4. 同時保存舊行號與新行號，行號從 1 開始；新增行沒有舊行號，刪除行沒有新行號。區塊顯示前後位置，正文 gutter 顯示對應標記。
5. 預設正文顯示目前內容，新增行加淡色背景，刪除內容在修訂卡片中查看；可切換唯讀「完整標記」投影，在原位置顯示舊行與新行。刪除行是展示資料，不插入真實編輯 document，也不計入字數、搜尋或匯出。
6. 章節新增／刪除在設定區列物件事件，正文仍提供全部新增／刪除行預覽；兩類統計分開標籤，不加成含義不明的總修改數。

## SideBar：物件與欄位差異

| 情況 | 物件標記 | 欄位呈現 |
| --- | --- | --- |
| 新增角色、章節、設定項目 | `+` | 展開顯示新欄位值，不列一串重複的欄位事件 |
| 刪除整個項目 | `-` | 展開顯示舊欄位值，供查閱或拒絕刪除 |
| 既有項目的欄位新增 | `*` | 該欄位 `+`，顯示新值 |
| 既有項目的欄位移除 | `*` | 該欄位 `-`，顯示舊值 |
| 既有欄位的值改變 | `*` | 該欄位 `*`，顯示「舊值 → 新值」 |
| Table 項目欄位新增 | `+` | 顯示新Table欄位 |
| Table 項目欄位移除 | `-` | 顯示舊Table欄位 |
| Table 項目欄位變更 | `*` | 顯示Table欄位「舊值 → 新值」 |

以穩定物件 ID + 欄位路徑配對，不能用名稱、陣列索引或本地化標籤當身份。角色改名是 `* / 名稱`，不是刪除加新增。SideBar 物件標題及實際欄位旁也顯示小標記；點標記會選中對應修訂卡片。

範例：`角色／林澪／年齡：17 → 18`、`角色／林澪／外觀／髮色：黑 → 銀`、`章節／第一章／名稱：出發 → 夜行`。巢狀欄位展開到實際變動的葉節點。集合使用成員穩定 ID／語義鍵比較；有意義的排序或父項目移動顯示 `* / 排序、所屬`，忽略其他項目因插入而發生的索引平移。

缺少欄位、null、空字串必須由各欄位的 schema 決定是否等價，不能一律當作相同；固定存在的文字欄位從「有值」改成空字串仍為 Modify。排除儲存時間、快取、計算字數、UI 狀態與 wire schemaVersion 等非使用者內容。

標籤、關係、物品分配、時間軸及快照資料需各自定義集合／關聯差異。可呈現細節，但接受／拒絕必須遵守依赖與資料完整性；例如物品分配與相關時間軸事件可能需要整組處理。

## 接受與拒絕

- 接受：保留目前值，將該差異標為已接受；不將整個基準切換成目前專案，以免其他未審閱差異消失。
- 拒絕：透過目前既有更新入口，把該欄位或正文區塊還原成基準內容；支援 Undo。正文替換區塊的刪除與新增一起處理。
- 接受狀態綁定精確的 old/new 值或內容摘要；接受後又被修改時產生新的待審閱差異。可用審閱覆蓋狀態維持原基準，接受後視圖預設隱藏但仍可查閱。
- 審閱動作前重新確認目前版本與差異前提。若內容已改變，重新計算並提示；不可按過期 offset 還原。遠端變更同樣使相關結果失效。
- 整個物件的新增／刪除按物件審閱；有依赖的操作使用交易整組處理。先提供逐筆，再提供目前範圍「全部接受／拒絕」，範圍名稱與數量需明确可見。
- 追蹤工作階段、基準、審閱狀態需持久化且隸屬專案；不得每次儲存改動基準。追蹤結束與建立新基準是明確獨立操作。精確多人審閱協定留待後續設計，不能直接等同 P2P merge ACK。

## 建議實作結構

- `features/revision_tracking/domain/`：`RevisionBaseline`、`TextDiffHunk`、`FieldChange`、`RecordChange`、`ReviewDecision`；包含穩定 ID、前後值／行號、來源版本及定位資訊。
- `features/revision_tracking/application/`：正文 line diff、設定 schema-aware diff、定位及審閱服務；不從 widget 文字反推模型差異。
- `presentation/providers/revision_tracking_provider.dart`：追蹤基準、篩選、選取、計算狀態與審閱狀態；以章節及物件粒度失效快取。
- `features/revision_tracking/presentation/`：窗格、摘要、正文區塊卡片、欄位卡片與標記。SideBar 各表單透過共用欄位 wrapper 接入 badge／定位。
- `main.dart` 接三欄排列；`bin/content.dart` / 現有 Quill editor 接入 gutter 與 readonly 標記投影。依現有 overlay 設計確認實際 offset／折行 mapping，不把 diff 列直接當編輯器行。
- `ProjectRecordCodec` 已有穩定 ID 的 record 快照，可作設定差異轉接起點；其刻意不包含章節正文，所以正文走獨立章節內容快照，其他協作文字也須確認是否完整包含。
- `project_snapshot_utils.dart` 可作快照基礎；`project_history_provider.dart` 是 Undo 歷史，不直接當作持久化追蹤基準。P2P revisions 只在完整內容可取得時提供比較來源；現有 merge service 的領域依赖規則需個別評估後復用。

大正文使用 debounce（建議 250–400ms）、背景 isolate、章節粒度快取及虛擬清單；IME 組字期間延後發布差異。計算結果附基準／目標版本，丟棄過期結果。跨章節跳转前同步編輯器草稿，避免比较漏掉未寫回模型的正文。首次全專案比較提供進度，不阻塞輸入。

## 分階段交付與驗收

1. **唯讀 MVP**：固定基準、三欄窗格、正文逐行差異、核心 SideBar 欄位差異、點擊定位、篩選與統計。尚未實現審閱時不顯示可操作的接受／拒絕鈕。
2. **標記整合**：正文 gutter／完整標記投影、SideBar 物件及欄位 badges、巢狀欄位與集合、窄螢幕布局。
3. **完整修訂追蹤**：基準與審閱持久化、接受／拒絕、Undo、過期差異防護、依賴交易與範圍批次操作。
4. **歷史與協作**：持久化版本選擇、操作來源／作者追蹤及多人審閱政策。

必要驗證：插入一行 `+1`、刪除一行 `-1`、改寫一行 `+1/-1`；視窗縮放不改變差異；空行、末尾換行、重複行、中文與 emoji 不造成錯誤定位；欄位改名仍為 Modify，單欄位變動不会显示整个物件全欄位修改；刪除最後一行或整個物件仍可查看與定位；接受後再修改重新出現；拒絕與 Undo 可恢復；遠端變動或快速連續輸入不套用過期結果；重啟保留追蹤基準；窄螢幕不溢位。
