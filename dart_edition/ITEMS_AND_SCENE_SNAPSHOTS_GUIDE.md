# 物品與 Scene 快照使用及遷移說明

> 文件入口：[統一說明文件](../docs/GUIDE.md#5-角色地點物品與-scene-快照)；本文件承接物品與 Scene 快照的詳細操作與遷移規則。

本文件適用於專案格式 **1.18**。物品、角色與地點共用時間軸的 Scene placement；使用者在時間軸移動播放頭後，各頁會投影該 Tick 當下的狀態。狀態變更以 Scene UUID 為主要連結，Tick 只作排序與 placement 遺失時的 fallback。

## 物品模式

| 模式 | 資料形態 | 適用情境 |
| --- | --- | --- |
| 專用 | 一個 Class 與一個獨立 instance ID | 唯一、需要追蹤個別歷史的物品 |
| 半專用 | 一個 Class，可展開多個有固定 instance ID 的物品，也可保留尚未具名的聚合數量 | 同類物品中只有部分需要個別追蹤 |
| 非專用 | 一個 Class，以分配數量記錄持有人、地點及未分配量 | 可互換、只需統計數量的物品 |

物品頁的模式開關會先預覽轉換。轉換建立新的 Class 或 instance 時，原 ID、既有快照與關聯會封存保留，避免改寫故事早期歷史。若數量未知、引用不完整或預覽後資料已變更，系統會拒絕提交並要求重新預覽。

## 建立與連結物品

1. 從側邊欄進入「物品」，建立 Class 並選擇專用、半專用或非專用。
2. 專用模式會使用獨立 instance；半專用可展開 Class 後建立或查看各件 instance；非專用直接編輯聚合分配量。
3. 使用物件選擇器把物品連到人物、地點、事件或場景。人物、地點及事件頁也能反向選取正式物品。
4. 人物與地點頁會依目前 Tick 顯示物品及數量。專用 instance 顯示單件，非專用 Class 顯示聚合量。
5. 舊人物持有物或大綱中的物品文字可逐筆連到既有物品，或轉成新的正式物品資料；提交前會提供預覽。

## Scene 快照

新增物品、角色或地點狀態時，先選 Scene。若同一 Scene 有多個 placement，可指定來源 placement；未指定時依最早 Tick、軌道順序及 placement ID 決定。移動 Scene 後，快照會跟隨新的 Tick；來源 placement 被移除時，資料仍保留並使用 fallback Tick。

地點樹的每個節點都有獨立快照，可記錄存在、可進入、狀態、控制者及自訂屬性。批次建立會先逐節點顯示前後差異，再以同一交易提交。父節點在某 Scene 不存在時，仍會保留具有獨立狀態的子節點樹殼供追溯。

故事中物品或地點的消失，應建立 Scene 快照並關閉「此時已存在」。永久刪除地點會先列出子樹、地點快照、物品關聯與位置記錄的影響，確認後清除相關引用。

## 1.18 格式與遷移

- 1.18 保存物品 Class、instance、正式關聯、Class／instance 快照、地點節點快照與轉換來源。
- 1.17 及更早的支援格式在開啟時只於記憶體升級；原檔在使用者儲存前不會被覆寫。下次正常儲存或另存後，檔案版本寫為 1.18。
- 缺少 UUID 的舊資料會建立穩定識別並回報遷移警告。找不到可靠目標的引用保留原 ID 或原文字，不會依同名項目自動配對。
- 比 1.18 更新的格式會被拒絕，以免舊版程式覆寫未知欄位。
- Markdown 局部匯出以可讀內容加 lossless XML 區塊保存結構化資料；XML 局部匯出可重新匯入。匯入時可只選物品、人物、世界設定或大綱等模組，未選模組維持原值。

## 協作相容性

即時協作協議目前使用 schema 6。物品轉移、拆分、模式轉換及地點批次快照可能包含多筆 record；同一交易的片段會在接收端收齊後一次套用，因此遠端不會看到半完成狀態。

協作雙方應使用支援專案格式 1.18 與協作 schema 6 的版本。協議版本不符時應停止該次即時協作，先各自保存專案，再升級應用程式。P2P snapshot 仍以完整雜湊與 XML 驗證決定是否接受；衝突時使用欄位衝突對話框或另存副本。

## 備份與復原

1. 升級舊專案前先使用「另存為」保留原檔，或在設定中開啟自動備份並確認備份目錄與容量上限。
2. 開啟舊檔後查看遷移警告，抽查同名人物／物品、地點子樹、Scene placement 與數量，再另存為 1.18。
3. 一般新增、批次快照及模式轉換會進入專案 undo／redo 歷史；永久刪除確認後仍應立即儲存或以備份復原跨工作階段資料。
4. P2P 衝突若無法安全直接套用，選擇另存副本；不要以舊版本程式重新儲存 1.18 專案。
5. 局部匯入會建立可復原的專案歷史節點。失效引用可保留，之後使用物件選擇器重新連結。

## 目前限制

- Scene 尚未排入時間軸時使用 fallback Tick；建立 placement 後才會依正式位置排序。
- 同一 Scene 的多個 placement 若未明確指定來源，會使用固定排序規則選出第一個，介面會標示解析來源。
- 封存物品可供歷史查詢，預設不顯示於目前管理清單。
- Windows profile 基線已涵蓋桌面與窄螢幕；視窗縮放與首次開啟對話框仍可能產生約 246ms 的 raster P95，後續版本應持續量測並優化首次 shader／surface resize 成本。
- 既有 `bin/file.dart` 與部分 view/provider 仍有已列管的傳遞依賴循環；guardrail 會阻止新增循環，完整解耦留待後續維護。
